# GYOZA

[日本語](README.ja.md)

A cooking-robot research project combining visual orchestration with specialized manipulation policies in MuJoCo.

![SO-101 kitchen simulation](docs/assets/kitchen_overhead.png)

## Idea

GYOZA separates object selection and outcome verification from motion execution. A vision-language orchestrator calls specialized ACT skills trained on synthetic demonstrations generated by a hybrid RL-and-scripted expert.

## Current status

- An ACT pick-and-place policy trained on **261 synthetic episodes** achieved **38/50 successes (76%)** in simulation. The [policy](https://huggingface.co/YUGOROU/act_gyoza_pickplace_synth) and [dataset](https://huggingface.co/datasets/YUGOROU/gyoza-pickplace-synth) are available separately.
- A five-step coupe-glass plating experiment completed **10/75 sequences without verification** and **14/75 with VLM verification and retries**. The difference was not statistically distinguishable.
- The repository includes data generation, ACT training and evaluation, and an MCP-based orchestration demo with replay.

## How it works

1. A hybrid expert combines PPO grasping with scripted transport and release.
2. Successful trajectories and overhead RGB observations become ACT training data.
3. Specialized ACT policies execute manipulation skills.
4. The demo orchestrator selects objects, calls skills through MCP, and checks outcomes to direct retries.

## Notes

Results are simulation-only. The scene contains two SO-101 arms, but the pick-and-place baseline holds the helper arm fixed. The verification ablation uses a scripted sequence, not the demo agent; earlier zero-shot VLA tests used a different scene layout.

Experiment jobs require external models, assets, and Linux rendering infrastructure. Job scripts contain commands and parameters. Code is MIT-licensed; external assets and dependencies retain their own licenses.
